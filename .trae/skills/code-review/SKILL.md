## 核心约束（强制执行）

### WORKFLOW-002: 审查任务执行模型

```yaml
约束项:
  - 审核文件数≥2时，必须为每个文件创建独立的审查执行任务
  - 每个审查任务必须独立执行，不得共享状态或资源
  - 审查任务必须按顺序逐一执行
  - 每个审查任务必须独立生成对应的审核报告文件
  - 【严禁】生成跨文件的汇总审查报告
  - 【严禁】报告引用或汇总其他文件信息

违规处理:
  - 检测到汇总报告生成请求: 立即终止并报错
  - 报告数量≠文件数量: 补生成或终止执行
```

### WORKFLOW-006: 多文件审查输出规范

```yaml
约束项:
  - 必须为每个被审查的完整文件创建独立的问题分析章节
  - 每个文件章节必须包含文件基本信息（文件名、总行数、文件路径）
  - 问题必须按严重程度分组（高/中/低优先级）
  - 必须使用标准表格格式（7个必需字段）
  - 【严禁】任何形式的跨文件汇总统计或整体评估
  - 【严禁】单文件报告依赖其他文件信息

表格必需字段:
  1. 问题类型
  2. 规则ID
  3. 严重程度
  4. 文件路径
  5. 具体位置
  6. 代码片段
  7. 建议改进措施
```

### WORKFLOW-007: 代码审查报告输出规范

```yaml
约束项:
  - 文件格式: Markdown (.md)
  - 文件名格式: review-[审查文件名]-[15位时间戳]
  - 时间戳格式: yyyyMMddHHmmsss
  - 输出目录: ./codeReview/
  - 【自动触发】审查文件数量≥2个时，自动触发文件生成
  - 【强制生成】用户查询包含"生成/创建/输出/保存/导出/文件"时强制生成

示例:
  - 正确: review-QueryCmEcVpnMebCSVImpl-202603181230450.md
  - 错误: code-review-result.md、review-all-files-202603181230450.md
```

## 执行流程

### 阶段1: 初始化与验证

1. **读取规则文件**
   - 加载8个规则文件到内存
   - 验证规则文件完整性

2. **统计待审查文件**
   - 扫描指定目录/文件列表
   - 统计文件数量 N

3. **模式判断**
   ```
   if N >= 2:
       进入多文件独立报告模式
       设置强制生成标志
   else:
       进入单文件审查模式
   ```

4. **创建输出目录**
   - 检查 `./codeReview/` 目录
   - 不存在则自动创建

### 阶段2: 逐文件审查（循环执行）

对于每个文件 file[i]:

1. **读取文件内容**
   - 读取完整文件内容
   - 统计总行数

2. **识别文件层级**
   - 文件名以 `CSVImpl.java` 结尾 → CSV层
   - 文件名以 `SV.java` 结尾 → Service层
   - 文件名以 `DAOImpl.java` 结尾 → DAO层
   - 其他 → 通用规则

3. **应用规则检查**
   - 根据层级选择对应规则子集
   - 逐项检查代码合规性
   - 记录违规项（规则ID、位置、代码片段、建议）

4. **生成独立报告**
   - 使用模板生成报告内容
   - 文件名: `review-{filename}-{timestamp}.md`
   - 保存到 `./codeReview/` 目录

5. **验证报告生成**
   - 确认文件已创建
   - 记录到生成清单

### 阶段3: 合规性验证

1. **数量验证**
   ```
   assert 报告文件数量 == 待审查文件数量
   ```

2. **内容验证**
   ```
   for each 报告文件:
       assert 不包含其他文件名
       assert 不包含"汇总"、"总结"、"整体"等关键词
       assert 不包含跨文件比较内容
   ```

3. **违规处理**
   - 发现汇总报告: 立即删除并报错
   - 数量不符: 补生成缺失报告
   - 内容违规: 重新生成违规报告

### 阶段4: 输出确认

1. **生成报告清单**
   - 列出所有生成的报告文件
   - 显示文件路径和大小

2. **统计信息**
   - 审查文件总数
   - 生成报告总数
   - 发现问题总数（按严重程度分组）

3. **合规确认**
   - 确认无汇总文件
   - 确认每个报告独立完整

## 使用方式

### 方式1: 审查目录下所有文件

```
使用 code-review 技能包审查 rulecenter/src/com/asiainfo/rule/person/impl/ 目录下所有Java文件
```

**执行过程**:
1. 扫描目录，发现24个Java文件
2. N=24≥2，触发多文件独立报告模式
3. 循环生成24个独立报告
4. 验证无汇总文件
5. 返回报告列表

### 方式2: 审查指定文件列表

```
使用 code-review 技能包审查以下文件：
- File1.java
- File2.java
- File3.java
```

**执行过程**:
1. 解析文件列表，N=3
2. 触发多文件独立报告模式
3. 为每个文件生成独立报告
4. 验证合规性

### 方式3: 单文件审查

```
使用 code-review 技能包审查 File1.java
```

**执行过程**:
1. N=1，进入单文件模式
2. 生成单个报告（不强制输出文件）
3. 在上下文中输出审查结果

## 违规处理机制

| 违规场景 | 检测方式 | 处理方式 |
|---------|----------|----------|
| 生成汇总报告 | 关键词匹配（汇总/总结/整体/total/summary） | 终止执行，报错提示 |
| 报告数量不足 | 生成后计数验证 | 补生成缺失报告 |
| 跨文件引用 | 正则匹配其他文件名 | 删除引用内容，重新生成 |
| 缺少必需字段 | 模板字段检查 | 补充缺失字段 |
| 表格格式错误 | Markdown表格验证 | 重新格式化 |
