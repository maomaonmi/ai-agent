# AI 写作工作台 V1 规格与实施计划

> 状态：产品方案已确认，可进入 V1 实施  
> 版本：V1 Draft  
> 日期：2026-08-12  
> 范围：第一版场景框架、交互骨架、提示词与模型路由接口；不在本阶段完成专用模型调用和完整提示词内容。

## 1. 目标

在现有“更多 → AI 写作”入口下新增一个独立的 AI 写作工作台。用户可以选择写作场景和参数、输入主题或原文，并以统一方式发起写作任务。

V1 的核心价值不是一次性实现全部写作能力，而是建立一个长期可扩展的基础：

- 一个统一工作台承载所有写作场景，不复制八套页面。
- 场景、字段、默认值和选项全部由配置文件驱动。
- 提示词工程放在独立目录，通过稳定接口编译，V2 可逐场景补充。
- 模型选择通过路由配置完成，UI 不直接绑定具体千问模型。
- 后续增加公文、邮件、自媒体等场景时，只需增加配置和提示词模块。

## 2. 用户与核心任务

目标用户包括学生、职场用户、内容创作者和需要处理长材料的研究用户。

核心用户流程：

1. 用户从输入框“更多”菜单点击“AI 写作”。
2. 打开独立写作工作台，默认选中“通用”。
3. 用户输入主题、要求或粘贴待处理原文。
4. 用户选择场景及其动态参数。
5. 系统将输入和配置编译为统一写作请求。
6. V1 通过当前默认模型进入现有生成链路；V2 再按任务自动路由专用模型。
7. 输出显示在写作结果区，并保留当前配置和草稿。

## 3. 已确认的产品原则

### 3.1 单工作台、配置驱动

八个场景共享同一输入区、参数栏、附件入口和输出容器。场景切换只更新参数，不切换页面，不造成布局跳动。

### 3.2 用户显式选择优先

参数优先级固定为：

```text
用户显式选择 > 意图模型建议 > 场景默认值
```

未来接入意图识别时，只能建议配置，不得静默覆盖用户已经选择的值。

### 3.3 场景参数与模型名称解耦

普通用户只选择任务。模型名称只在高级设置或调试信息中可见，避免将模型市场暴露成复杂表单。

### 3.4 长文分阶段生成

3000 字以上的任务预留“大纲 → 分段生成 → 全文整理”工作流。V1 只搭状态和接口，不承诺一次请求生成 30000 字成品。

### 3.5 独立 Writing 模式与延迟建会话

- AI 写作使用独立的 `writing` 模式，与标准聊天、Code 工作台分离。
- 点击“AI 写作”只打开未落库的写作草稿，不立即生成历史会话。
- 用户第一次提交写作需求时才创建 `writing` 会话并进入历史侧栏。
- 未提交就退出时，仅按本地草稿策略保留内容。

### 3.6 V1 采用轻文档工作区

- V1 输出采用“单篇正文 + 修改指令”，不渲染聊天气泡。
- 正文是主工作对象，修改指令是后续迭代入口。
- 完整版以产品参考图为方向，演进为左右双栏：左侧需求与修改指令，右侧文档工作区。
- 完整版右侧预留“大纲 / 正文 / 排版”视图，以及大纲节点、分步生成、引用资料和保存状态。

## 6. 交互规格

### 6.1 场景切换

- 点击场景卡片后立即更新参数栏。
- 每个场景保存自己的最后一次选择；来回切换时不丢失。
- 切换场景不清空输入文字或附件。
- 参数菜单必须支持键盘操作、Esc 关闭和点击外部关闭。

### 6.2 输入框

- 初始高度约 3 行，随内容自动增长，达到上限后内部滚动。
- 通用写作、小说等主题型任务允许只输入短描述。
- 仿写、润色、扩写、缩写、续写等原文依赖任务，缺少原文时在提交前显示轻量校验。
- 支持文本文件作为素材；V1 沿用现有附件能力，不新增解析服务。

### 6.3 字数

- UI 显示用户选择的目标字数，而不是模型 Token 数。
- 编译请求时把目标转换为允许范围，例如 500 字对应约 450–600 字。
- 输出区显示实际字数。
- V1 对 3000 字以上显示“长文将分阶段生成”的说明；具体章节编排留到 V2。

### 6.4 草稿状态

- 页面刷新后保留场景、参数和未提交文本，使用 `localStorage`。
- 提交成功后不自动清空输入，方便继续修改要求。
- V1 不新增数据库表，不将未提交草稿写入服务器。
- 提供明确的“清除本地草稿”入口；损坏或版本过旧的数据应安全回退为默认值。

### 6.5 论文研究能力提示

- V1 在论文场景显示“资料研究 · 即将支持”的禁用入口。
- 禁用状态必须有说明，不能让用户误以为已经启用文献检索或引用核验。
- V2 接入 Deep Research 后再开放研究计划、来源与引用状态。

### 6.6 模型高级设置

- 普通界面隐藏具体模型名称，默认采用“自动路由”。
- 高级设置提供“自动 / 手动覆盖”，手动覆盖只对当前写作任务或会话生效。
- 若指定模型不可用，必须提示并允许回退，不能静默切换。

### 6.7 响应式与可访问性

- 320px、768px、1024px、1440px 下无横向溢出。
- 桌面场景栏可横向滚动但隐藏突兀滚动条；选中项自动滚入可见区域。
- 所有交互使用原生按钮，存在明确的 hover、focus、selected、disabled 状态。
- 正文与控件文字达到 WCAG AA 基本对比度。
- 尊重 `prefers-reduced-motion`，减少非必要动画。

## 8. 提示词工程接口

V1 建立接口和占位模板，不追求最终内容质量。

```ts
export interface WritingPromptContext {
  scene: WritingSceneId;
  instruction: string;
  sourceText?: string;
  parameters: Record<string, string>;
  targetLength?: number;
}

export interface CompiledWritingPrompt {
  systemPrompt: string;
  userPrompt: string;
  constraints: string[];
  routingHints: WritingRoutingHints;
}

export type WritingPromptCompiler = (
  context: WritingPromptContext,
) => CompiledWritingPrompt;
```

每个场景一个编译器文件，统一通过 `prompts/index.ts` 注册。组件不能直接拼接 system prompt。

V2 模板统一包含：角色与能力、任务目标、用户素材、场景参数、结构要求、风格要求、长度约束、事实与引用约束、输出格式。

## 9. 模型路由设计

V1 只输出路由建议，最终调用现有模型；V2 才接入专用模型。

```ts
export interface WritingRoutingHints {
  capability:
    | 'general-writing'
    | 'character-writing'
    | 'deep-research'
    | 'long-context';
  requiresSourceText: boolean;
  prefersOutlineFirst: boolean;
  requestedLength?: number;
}
```

建议规则：

- 普通作文、总结、申请书和短文本：当前高质量通用模型。
- 小说人物对白与角色连续互动：预留 `qwen-plus-character` / `qwen-flash-character`。
- 小说大纲、叙事结构和完整章节：仍以通用生成模型为主。
- 论文资料研究：预留 `qwen-deep-research`，研究结果再交给通用模型成文。
- 长材料仿写、润色、总结和长篇续写：预留 `qwen-long`。
- 自动场景识别和工具选择：预留 Tongyi-Intent-Detect，仅产生建议。

模型路由必须在后端再次校验；前端提示只用于体验，不作为安全或计费边界。

## 12. 测试策略

### 单元测试

- 八个场景配置完整，字段与默认值合法。
- 场景切换后生成正确参数集合。
- 原文依赖任务的校验准确。
- 字数映射和长文路由提示准确。
- 提示词注册表能解析全部场景。
- 路由器不会让意图建议覆盖显式选择。

### 组件测试或静态回归

- AI 写作入口打开独立工作台。
- 所有下拉框可以键盘操作。
- 输入框自动增高。
- 切换场景保留输入内容和各自参数。
- 移动端参数收纳，无横向溢出。

### 集成验证

- 通用场景提交可以进入现有流式生成链路。
- 请求携带正确的 writing context。
- 错误、停止和重新生成不会丢失草稿。

### 命令

```powershell
cd frontend/ai-agent
npx tsc --noEmit
npx eslint src/features/ai-writing src/components/ChatInterface.tsx
npm run build
```

## 13. 分阶段实施

### Phase A：配置与类型基础

1. 定义统一类型、八个场景配置和默认状态。
2. 建立提示词目录、注册表和 V1 占位编译器。
3. 建立模型路由接口和默认通用路由。

检查点：配置和编译器单元测试通过，页面尚未接入也不会影响现有聊天。

### Phase B：可交互工作台

4. 新增 AI 写作独立视图和入口路由。
5. 实现主输入卡片、自动增高和附件入口。
6. 实现场景导航、动态参数栏和可访问下拉菜单。
7. 实现移动端写作设置抽屉和响应式布局。

检查点：八个场景均可选择，所有参数与需求一致，切换不丢输入。

### Phase C：生成闭环

8. 将写作配置编译成统一 writing context。
9. 接入现有流式生成与停止能力。
10. 实现结果区、实际字数、错误和重试状态。
11. 保存本地草稿和每场景的最后选择。

检查点：至少通用、作文、小说、论文四条代表性链路端到端可用。

### Phase D：质量验收

12. 完成键盘、焦点、移动端和减少动效检查。
13. 完成类型检查、限定 lint、生产编译和浏览器视觉验收。
14. 更新本计划的实际完成状态与 V2 待办。

## 14. 风险与缓解

| 风险 | 影响 | 缓解方案 |
|---|---|---|
| 大量选项导致 UI 拥挤 | 高 | 配置摘要 + 响应式抽屉；桌面只展示当前场景字段 |
| 场景配置和提示词逻辑重复 | 高 | 场景定义为唯一数据源，提示词使用注册表 |
| 30000 字一次生成失败 | 高 | 3000 字以上标记长文流程，V2 分章生成 |
| Character 模型误用于所有小说任务 | 中 | 路由细分“角色互动”和“叙事写作”能力 |
| 论文生成虚假引用 | 高 | V2 研究与成文分阶段，来源状态显式展示 |
| 意图模型覆盖用户选择 | 中 | 固定优先级并写入单元测试 |
| 专用模型接口变化 | 中 | 后端适配器隔离具体模型名，前端仅传能力提示 |
| 本地草稿含敏感材料 | 中 | V1 明示本地保存，可一键清除；不默认同步服务端 |

## 15. 边界

### 始终执行

- 场景、选项和默认值只有一个数据源。
- 所有新增控件具备键盘和焦点状态。
- 提示词不写在 React 组件里。
- 专用模型路由必须具备通用模型回退路径。
- 每个阶段通过验证后再进入下一阶段。

### 实施前需确认

- 是否新增第三方依赖。
- 是否在 V1 接入任何千问专用模型（当前默认不接入）。
- 是否允许上传整本书、论文资料包等大型文件（当前按现有附件能力处理）。

### V1 不做

- 不实现完整的八套高质量提示词。
- 不实现联网文献检索和引用核验。
- 不实现多角色小说协作。
- 不实现 30000 字一次性生成。
- 不实现多人协作、云端草稿或作品发布。

## 16. 成功标准

- “更多 → AI 写作”可稳定打开独立工作台并返回原界面。
- 八个场景及所有已确认选项均正确显示。
- 每个场景只显示自己的参数，默认值正确。
- 场景切换不丢输入，各场景配置可恢复。
- 输入框支持长文本，桌面和移动端均无布局溢出。
- 提示词和模型路由存在独立、可测试的接口文件。
- 至少一条 V1 生成链路可使用现有模型完成流式输出。
- TypeScript 检查通过，新增文件限定 lint 通过。
- 用户提交前不把未提交草稿创建为历史会话。

## 17. 已确认的产品决策

1. AI 写作使用独立的 `writing` 历史会话模式。
2. 打开工作台时不落库，第一次提交后才创建会话。
3. V1 使用“单篇正文 + 修改指令”的轻文档工作区，不复制聊天气泡；完整版按参考图演进为双栏文档工作台。
4. 字数选项采用本计划列出的递增档位。
5. 小说篇幅在 V1 仅作语义标签，V2 再映射章节和字数。
6. 论文资料研究在 V1 显示为不可用的“即将支持”。
7. 模型选择默认隐藏，仅在高级设置提供“自动 / 手动覆盖”。
8. 草稿默认本地保存，并提供清除入口。

## 18. V2 预留

- 为八个场景补充正式提示词模板和版本管理。
- 接入 Tongyi-Intent-Detect，提供可撤销的场景和参数建议。
- 接入 Character 模型处理角色设定、对白和角色一致性。
- 接入 Deep Research 完成论文研究计划、检索、来源整理和引用状态。
- 接入 Qwen-Long 处理长附件、整书阅读和超长原文变换。
- 增加长文大纲、章节队列、断点续写和全文一致性检查。
- 增加版本历史、段落级重写、长度调整和导出能力。
