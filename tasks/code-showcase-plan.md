# Code 作品广场与发布闭环实施计划书

## 1. 项目概述

在现有 Code 模式之上增加一个独立的“代码作品广场”，让用户能够浏览示例、复用完整提示词，并把 Code 工作台生成的项目发布为长期作品。

本功能解决三个问题：

1. 新用户面对空白输入框时缺少可直接复用的范例。
2. Code 模式生成结果目前只属于会话，缺少展示与沉淀入口。
3. 当前输入框是单行控件，无法承载较长的“同款指令”和优化后提示词。

第一阶段强调“框架完整、视觉现代、数据可靠”，不要求把所有示例应用真实开发出来。

## 2. 产品目标与成功标准

### 2.1 目标用户

- 想快速生成网页、工具或互动内容，但不会完整组织提示词的用户。
- 已经在 Code 模式生成项目，希望保存和展示成果的用户。
- 想从现成作品出发继续修改，而不是从零描述需求的用户。

### 2.2 核心用户旅程

1. 用户点击输入框“更多 → 代码”。
2. 进入代码作品广场，浏览分类与封面卡片。
3. 点击“同款指令”，完整提示词进入可自动增高的输入框。
4. 用户可直接发送，也可先点击“优化指令”。
5. 用户在 Code 工作台完成生成后点击“发布到作品广场”。
6. 作品以独立副本保存；后续代码修改形成“有待发布更新”状态。
7. 即使来源会话被删除，作品仍保留最后一次正式发布的内容。

### 2.3 可测试的成功标准

- “更多 → 代码”进入独立作品广场，不与普通聊天消息混排。
- 页面在 320、768、1024、1440px 宽度下无横向溢出。
- 示例卡片具备标题、封面、分类和“同款指令”入口。
- “同款指令”完整填入输入框，不自动发送，并正确撑高输入框。
- 输入框初始为单行，按内容增长，达到最大高度后内部滚动。
- Code 工作台能够创建或更新一个已发布作品。
- 删除来源会话后，作品列表、封面、提示词与最后发布代码仍可读取。
- 删除作品与删除会话是两个独立操作。
- 键盘可访问主要控件，焦点状态清晰，正文与按钮达到 WCAG AA 对比度目标。

## 3. 范围定义

### 3.1 MVP 包含

- 独立代码作品广场视图。
- 顶部欢迎区、Code 专用输入框和分类导航。
- 全部、实用工具、网页设计、娱乐互动、教育学习五个分类。
- 12–20 个静态种子作品及现代化封面。
- 响应式作品卡片网格。
- 卡片悬停/聚焦显示“同款指令”。
- “同款指令”填充完整提示词。
- “优化指令”按钮和现有优化能力的接入位置。
- 主聊天输入框改为自动增高 textarea。
- Code 工作台发布入口、发布表单和发布状态。
- 已发布作品独立持久化。
- 成功生成后标记“有未发布更新”。
- 删除会话不删除已发布作品。

### 3.2 暂不包含

- 点赞、收藏、评论、排行榜和关注关系。
- 多用户公共社区、内容审核与举报。
- 为所有种子卡片开发真实可运行项目。
- 每次文件敲击都自动覆盖正式发布版本。
- 多人协作、作品分叉和复杂版本树。
- 云端对象存储与 CDN；第一版沿用本地部署约束。

## 4. 视觉与交互设计规范

### 4.1 设计原则

- 内容优先：欢迎区不使用巨大空白，尽快露出分类和首屏作品。
- 克制现代：白色/浅灰底、清晰边界、低强度阴影，不使用大面积紫色渐变。
- 封面主导：卡片以预览图为视觉主体，标题与操作保持轻量。
- 渐进披露：默认只展示必要信息，悬停或键盘聚焦时出现“同款指令”。
- 状态明确：发布、待更新、同步成功、截图失败均有文字反馈，不只依赖颜色。

### 4.2 页面布局

- 顶部区域：返回入口、标题“和我一起 Coding”、简短说明。
- 创作区：自动增高输入框；左侧附件/Code 标签，右侧优化与发送按钮。
- 分类导航：吸顶或紧邻创作区，横向可滚动，当前项使用下划线与加粗双重提示。
- 作品网格：
  - 1440px：4 列，空间充足时允许 5 列。
  - 1024px：3 列。
  - 768px：2 列。
  - 320px：1 列。
- 卡片比例：封面建议 16:9；圆角 14–16px；边框优先于重阴影。

### 4.3 卡片状态

- 默认：标题、封面、分类或来源标签。
- Hover/Focus：边框增强，右上角显示“同款指令”。
- 我的作品：增加“已发布 / 有更新”状态，不使用醒目的营销徽章。
- 封面加载失败：显示与分类匹配的默认封面，不能出现空白破图。

### 4.4 输入框行为

- 使用 `textarea`，初始高度约 44–52px。
- 根据 `scrollHeight` 自动增长，最大高度 220px。
- 超过最大高度后内部滚动。
- `Enter` 发送，`Shift + Enter` 换行；输入法组合阶段不误发送。
- 同款指令填入后自动聚焦并将光标放到末尾。
- 优化指令期间显示明确加载态，避免重复提交。

## 5. 架构决策

### 5.1 作品与会话分离

当前 `vfs_checkpoints.session_id` 使用 `ON DELETE CASCADE`。如果作品仅引用 checkpoint，会话删除后作品必然丢失。因此已发布作品必须保存独立代码副本。

建议新增表 `published_code_projects`：

| 字段 | 类型/语义 |
|---|---|
| `project_id` | 独立 UUID 主键 |
| `source_session_id` | 可空的来源会话 ID，删除会话时置空 |
| `title` | 作品标题 |
| `category` | 受控分类枚举 |
| `prompt` | 原始完整提示词 |
| `optimized_prompt` | 可空的优化提示词 |
| `cover_image` | 封面路径或数据引用 |
| `vfs_blob` | 独立 VFS 代码副本 |
| `is_compressed` | VFS 是否压缩 |
| `project_kind` | frontend/fullstack |
| `published_run_id` | 最近正式发布来源运行 ID |
| `draft_run_id` | 最近生成成功运行 ID，用于判断待更新 |
| `created_at` | 创建时间 |
| `updated_at` | 更新时间 |
| `published_at` | 正式发布时间 |

数据库关系：

```text
sessions 1 ───── 0..n published_code_projects
           弱关联，ON DELETE SET NULL

published_code_projects 自己保存 prompt、cover 和 vfs_blob
```

### 5.2 正式发布与草稿更新

- 第一次发布：复制当前最新 VFS、提示词、项目类型与封面。
- 后续生成成功：只更新 `draft_run_id`，作品显示“有未发布更新”。
- 点击“更新发布”：重新复制最新 VFS 并更新封面与 `published_run_id`。
- 删除会话：`source_session_id` 置空，停止自动同步，正式发布副本保留。

这比“每次修改立即覆盖作品”安全，避免失败生成污染可展示版本。

### 5.3 封面策略

- 官方种子作品：使用项目内预制封面资源。
- 用户作品：优先从 Code 预览区生成截图。
- 截图失败：允许用户重新上传封面，并提供分类默认封面。
- 第一阶段封面存储可采用应用数据目录中的文件路径；数据库仅保存相对路径和元数据，避免 SQLite 被大量图片膨胀。

## 6. API 草案

### 6.1 作品查询

- `GET /api/code-projects?category=&source=&cursor=`
- 返回卡片所需轻量字段，不直接返回完整 VFS。

### 6.2 作品详情

- `GET /api/code-projects/{project_id}`
- 返回提示词、封面、状态与预览所需信息。

### 6.3 发布与更新

- `POST /api/code-projects`
- `PUT /api/code-projects/{project_id}`
- 服务端从请求中的已验证 VFS 创建独立副本。

### 6.4 删除作品

- `DELETE /api/code-projects/{project_id}`
- 只删除作品，不影响来源会话。

### 6.5 会话删除语义

- 保持现有会话删除接口。
- 数据库外键负责将作品的 `source_session_id` 置空。
- UI 删除确认文案明确：“不会删除已发布作品”。

## 7. 实施阶段与依赖关系

```text
作品数据模型
  → Store 与迁移兼容
    → REST API 与契约测试
      → 前端 API 类型
        → 作品广场只读框架
          → 同款指令/自适应输入框
          → Code 发布与更新闭环
            → 删除隔离验证
              → 视觉与无障碍 QA
```

### 阶段 A：规格与视觉骨架

1. 定义作品类型、分类、状态与种子数据结构。
2. 创建作品广场页面骨架和响应式卡片组件。
3. 使用真实中文标题和封面资产验证网格密度。

检查点：在四个目标宽度下布局稳定，尚不依赖后端即可浏览静态种子作品。

### 阶段 B：提示词复用体验

1. 主输入控件替换为自适应 `textarea`。
2. 实现同款指令填充、聚焦和滚动行为。
3. 接入或复用现有“优化指令”能力，并处理加载/错误状态。

检查点：长提示词可以编辑、换行、优化和发送，不挤成单行。

### 阶段 C：作品独立持久化

1. 新增作品表、存储类和数据库迁移兼容逻辑。
2. 实现查询、详情、发布、更新和删除接口。
3. 建立封面文件目录和路径校验。

检查点：后端契约测试通过；删除会话后作品仍存在。

### 阶段 D：Code 工作台发布闭环

1. 在 Code 预览工具栏增加“发布作品”入口。
2. 实现标题、分类、封面的轻量发布弹窗。
3. 成功生成后更新草稿状态，显式“更新发布”。
4. 从作品详情恢复代码时创建新会话，而不是修改原作品。

检查点：生成 → 发布 → 修改 → 待更新 → 更新发布全链路可用。

### 阶段 E：现代化视觉与质量收尾

1. 统一间距、字体层级、边框、阴影和交互动画。
2. 键盘、焦点、空状态、错误状态和封面失败状态检查。
3. 浏览器截图对比与 320/768/1024/1440px 响应式验证。
4. 运行类型检查、测试和生产构建；区分本功能问题与存量 lint 债务。

## 8. 测试策略

### 后端单元与集成测试

- 创建作品后可以按分类读取。
- 更新作品会替换正式 VFS，不产生半写入状态。
- 删除来源会话后作品仍存在且 `source_session_id = NULL`。
- 删除作品不删除来源会话或 checkpoint。
- 非法分类、空标题、超大封面与非法路径被拒绝。

### 前端组件测试

- 分类切换正确过滤卡片。
- 同款指令完整填入 textarea。
- textarea 随内容增长并在最大高度停止。
- 发布状态正确显示“已发布”和“有更新”。
- 菜单、卡片和发布弹窗支持键盘操作。

### 浏览器流程测试

1. 更多 → 代码 → 浏览作品。
2. 点击同款指令 → 输入框增长 → 优化 → 发送。
3. Code 工作台发布 → 广场出现作品。
4. 修改代码 → 出现待更新 → 更新发布。
5. 删除会话 → 重新打开广场 → 作品仍可预览。

## 10. 风险与缓解

| 风险 | 影响 | 缓解方案 |
|---|---|---|
| 会话删除级联清除代码 | 高 | 发布时复制 VFS；作品外键采用 `SET NULL` |
| 自动截图跨域或预览未稳定 | 中 | 等待预览稳定；失败时上传或使用默认封面 |
| 大型 VFS 增加数据库体积 | 中 | 复用 zlib 压缩；列表接口不返回 VFS |
| 示例过多导致首屏性能下降 | 中 | 首屏懒加载封面；MVP 控制在 12–20 个 |
| 提示词很长造成输入区失控 | 中 | textarea 最大高度 220px，之后内部滚动 |
| 自动同步覆盖可用版本 | 高 | 生成只标记草稿，正式更新必须显式确认 |
| 当前工作树存在存量 lint 错误 | 中 | 按文件验证；最终单独列出存量问题，不掩盖新错误 |

## 11. 边界约束

### 始终执行

- 先写失败测试，再实现数据与行为逻辑。
- 保存用户发布内容前校验类型、大小和路径。
- 发布与更新使用事务，避免元数据和 VFS 不一致。
- 每个阶段完成后进行可视化和交互验证。

### 实施中需要再次确认

- 是否允许作品对其他用户公开。
- 封面最终使用本地文件、对象存储还是数据库 BLOB。
- “优化指令”是否消耗真实模型调用，以及失败时是否保留原文。

### 明确禁止

- 作品只保存 checkpoint ID。
- 删除会话时连带删除已发布作品。
- 自动生成成功后未经确认直接覆盖正式发布版本。
- 用大量占位白框代替封面或忽略加载失败状态。

## 12. Definition of Done

- 所有 MVP 成功标准通过。
- 数据删除隔离有自动化回归测试。
- 四档响应式截图完成并检查。
- 关键页面无控制台错误。
- 新增代码无 TypeScript 错误和新增 lint 错误。
- 计划、接口语义和删除行为与最终实现一致。
