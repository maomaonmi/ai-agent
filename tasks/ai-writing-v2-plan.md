# AI 写作 V2：双栏研究型文档工作台计划

> 状态：待产品确认，暂不进入代码实现
> 版本：V2 Plan
> 日期：2026-08-12
> 目标：在 V1 轻文档工作区之上，建立参考千问截图的左右分栏写作工作台，承载论文研究、长文编排、角色协作、引用核验、版本管理与全文改写。

## 1. 本版目标

V2 不再把正文作为页面下方的结果卡片，而是把正文定义为工作台的核心文档对象：

- 左栏：用户需求、修改指令、研究进度、角色协作状态和会话输入。
- 右栏：正式文档区，展示大纲、正文和排版视图；生成内容直接写入文档区。
- 首次提交前仍是本地草稿，不创建历史会话；第一次提交才创建 `writing` 会话。
- 桌面端以截图中的左右分栏为规范基准；移动端采用“左栏/文档”切换，不制造横向溢出。

## 2. 视觉与布局基准

### 2.1 桌面工作台

```text
┌─────────────────────────────────────────────────────────────────┐
│ 顶栏：文档标题 · 保存状态 · 版本 · 设置                          │
├────────────────────────┬────────────────────────────────────────┤
│ 左栏（需求与协作）      │ 右栏（正式文档）                         │
│                         │ 视图：大纲 | 正文 | 排版                 │
│ 用户需求/历史指令        │ 文档标题                                 │
│ 研究/角色/章节状态       │ 摘要、章节、正文、引用                   │
│                         │                                          │
│                         │                                          │
│ 输入框 + 修改指令        │ 保存状态 / 生成下一节 / 版本对比          │
└────────────────────────┴────────────────────────────────────────┘
```

- 默认比例建议左 38% / 右 62%，中间分隔线可拖拽，范围 30%–50%。
- 右栏始终是文档工作区；禁止把正文追加到页面最下方。
- 左栏输入框固定在左栏底部，内容超长时仅输入区内部增长/滚动。
- 右栏使用文档纸张式表面：标题、摘要、一级/二级标题、正文段落、引用标记和参考文献分层显示。
- 颜色、圆角、阴影沿用现有设计系统，避免大面积渐变和过重卡片。

### 2.2 三种文档视图

1. **大纲**：章节树、章节状态、目标字数、引用数量和生成队列。
2. **正文**：正式阅读/编辑视图，生成结果直接落在此处。
3. **排版**：字号、行距、标题层级、引用样式和页宽预览；V2 先做预览，不承诺导出全部格式。

未生成时默认展示“大纲”引导；首次生成后自动切换到“正文”，符合“结果在右栏生成”的预期。

## 3. V2 能力范围

### 3.1 Deep Research 完整论文链路

论文流程为：

```text
需求解析 → 研究计划 → 多轮检索 → 来源筛选 → 摘要与证据卡片
→ 大纲生成 → 分章节写作 → 引用插入 → 引用核验 → 全文一致性检查
```

- 左栏显示当前阶段、来源数量、失败/重试和可暂停状态。
- 右栏显示研究大纲、正文和引用标记，不将搜索日志混入正文。
- V2 优先复用现有 `/deep_research` SSE 链路，统一适配为文档事件；后端提供能力降级提示。
- 引用必须绑定来源 ID、原文片段、URL、访问时间和置信状态，不能只生成裸链接。

### 3.2 Character 多角色协作

- 角色卡：角色名、职责、语气、关注点、输入材料和输出格式。
- 默认角色建议：研究员、结构编辑、正文作者、引用核验员、审校员。
- 左栏可查看角色状态和当前接力关系；右栏只接收经过编排的文档产物。
- 小说场景可切换 `qwen-plus-character` / `qwen-flash-character` 能力；具体模型名只在高级设置显示。
- 角色协作必须有超时、失败和人工接管，不允许无限自动循环。

### 3.3 30000 字章节编排

- 目标字数仅作为规划约束，不把 30000 字当成单次请求。
- 先生成章节树和每章目标字数，再按章节队列生成；每章完成后保存 checkpoint。
- 支持暂停、重试、重排章节和“只重写当前章节”。
- 全文完成前显示“已生成/目标字数、已完成章节/总章节、引用覆盖率”。

### 3.4 自动引用核验

- 每个引用包含：来源、对应正文句子、证据片段、核验状态。
- 状态至少包括：已核验、部分支持、未找到支持、待人工确认。
- 右栏正文中的引用标记可点击打开证据卡片；左栏显示待处理列表。
- 未核验引用不能以“已验证”视觉呈现，避免误导。

### 3.5 AI 意图自动识别

- 默认仅“建议”，不能覆盖用户已选场景、文体、学段、字数或模型设置。
- 提供“采纳建议 / 忽略 / 手动覆盖”操作和原因说明。
- 高级设置保留“自动 / 手动覆盖”；普通界面不展示具体模型名。
- 计划接入 Tongyi Intent Detect 时，只把结构化意图作为路由建议，后端再次校验。

### 3.6 版本对比与全文改写

- 每次完整生成、章节生成和用户确认改写都产生不可变版本快照。
- 版本对比支持全文级和章节级：新增、删除、修改、引用变化分开标识。
- “全文改写”先生成预览版本，用户确认后才替换当前正文；原版本永不覆盖。
- 支持恢复任一版本，并保留当前草稿的本地备份。

## 4. 数据与接口设计

### 4.1 文档状态模型

建议新增独立的 `WritingDocumentState`，不把整篇正文塞进聊天消息：

```ts
interface WritingDocumentState {
  documentId: string;
  sessionId?: string;
  title: string;
  scene: WritingSceneId;
  outline: WritingOutlineNode[];
  sections: WritingSection[];
  references: WritingReference[];
  activeSectionId?: string;
  targetLength?: number;
  generatedLength: number;
  versionId: string;
  researchStatus: 'idle' | 'planning' | 'searching' | 'writing' | 'verifying' | 'done' | 'failed';
}
```

### 4.2 事件协议

继续使用 SSE，但增加文档事件类型：

- `document_outline`：更新章节树。
- `document_section`：增量写入某一章节。
- `reference_found`：新增来源和证据卡片。
- `citation_check`：更新引用核验状态。
- `document_version`：创建版本快照。
- `writing_status`：更新阶段、进度、可重试状态。

现有聊天 `token` 事件保留兼容路径，避免影响标准对话、Code 和 V1 写作。

### 4.3 持久化边界

- 未提交草稿：继续默认本地保存，并提供清除入口。
- 首次提交后：创建 `writing` 会话，文档快照和版本保存到会话历史。
- 自动保存采用版本化写入，避免生成中途刷新导致正文丢失。
- 引用和研究来源与正文版本绑定；删除项目/会话不能删除已发布或本地备份内容。

## 5. 分阶段实施

### Phase 0：契约与迁移（高风险先行）

- 定义文档、章节、引用、版本和 SSE 事件类型。
- 为 V1 文档结果提供向 V2 `sections` 的兼容转换。
- 增加后端请求校验、事件回放和失败恢复测试。

**验收：** 旧会话可打开；新旧模式不互相污染；TypeScript/Python 契约测试通过。

### Phase 1：双栏工作台骨架

- 将 `WritingWorkspace` 拆为顶栏、左栏协作区、右栏文档区和移动端切换器。
- 首先实现静态大纲/正文/排版三视图、空状态、生成中、失败和保存状态。
- 正文只允许在右栏渲染；完成一次生成后自动切换正文视图。

**验收：** 1440/1024 桌面端严格左右分栏；320/768 移动端无横向溢出；键盘可操作。

### Phase 2：论文 Deep Research 链路

- 接入研究计划、来源列表、证据卡片、分章节写作和研究进度。
- 将现有 `/deep_research` SSE 适配为文档事件。
- 增加暂停、重试、取消和降级提示。

**验收：** 论文任务能够从需求进入研究计划并在右栏生成章节，来源状态可追踪。

### Phase 3：引用核验与文档样式

- 建立引用锚点到正文句子的映射。
- 实现核验状态、证据抽屉、未核验警示。
- 完成标题、摘要、章节、段落、引用和参考文献的明确文档样式。

**验收：** 任何引用都能追溯来源；未核验内容不会显示为已验证；右栏阅读层级清晰。

### Phase 4：Character 协作与长文编排

- 增加角色卡、角色接力、章节队列和 checkpoint。
- 支持 3000/8000/10000/20000/30000 字规划档位。
- 允许单章重试、重排和人工修改后继续生成。

**验收：** 30000 字任务以章节队列运行，刷新/暂停/重试不丢已完成章节。

### Phase 5：意图建议、版本对比与全文改写

- 接入意图识别建议层，并保留手动覆盖。
- 实现全文/章节版本树和 diff 视图。
- 实现预览式全文改写、确认替换和版本恢复。

**验收：** 自动建议不能覆盖显式选择；改写前后可比较；恢复版本后引用和章节结构一致。

### Phase 6：性能、无障碍和视觉验收

- 大文档虚拟化/分段渲染，避免 30000 字一次性压垮 DOM。
- 检查加载、流式生成、网络断开、恢复、键盘导航和 reduced motion。
- 按截图做同尺寸视觉对比，输出 `design-qa.md`。

**验收：** 关键流程无 P0/P1/P2 视觉问题；控制台无新增错误；主要交互可键盘完成。

## 6. 风险与防线

| 风险 | 影响 | 防线 |
|---|---|---|
| 30000 字一次性生成超时 | 高 | 章节队列、断点续写、幂等事件 |
| 引用看似完整但证据不足 | 高 | 来源/片段/状态绑定，未核验显式提示 |
| 多角色无限循环 | 高 | 最大轮数、超时、人工接管 |
| 右栏大文档渲染卡顿 | 高 | 分章节状态、虚拟化、增量更新 |
| 意图模型覆盖用户选择 | 中 | 建议层优先级低于显式选择 |
| V2 破坏 V1 会话 | 高 | 兼容转换、事件版本号、回放测试 |

## 7. 先确认的三个产品默认值

以下默认值不影响整体架构，但会影响第一批 UI 验收：

1. **右栏首屏**：推荐“未生成显示大纲，生成后自动切正文”；是否确认？
2. **Deep Research 引擎**：推荐优先复用现有 Qwen/研究 SSE 链路，失败时显示降级状态，不伪造引用；是否确认？
3. **版本节点**：推荐“每次章节完成 + 每次用户确认改写”自动建版本，同时保留手动保存；是否确认？

## 8. V2 完成定义

- 正文始终在右栏文档区生成，不再出现在页面下方。
- 论文研究、章节编排、引用核验、版本管理均有可见状态和可恢复路径。
- Character 与意图识别是受约束的编排能力，不是不可控的黑盒自动化。
- 所有未完成能力显示真实状态，不把占位功能伪装成已完成。
- V1 草稿、历史会话和标准对话保持兼容。
