# 自主任务规划性能与实时事件优化计划

## 目标

在不改变自主任务规划结果契约和会话持久化的前提下，降低搜索与模型调用等待，并让搜索、任务开始、任务产出在 SSE 中实时可见。

## 实施顺序

1. 搜索摘要模式：Plan 任务默认只使用搜索摘要，不进行全文 scrape；保留显式高级配置的扩展能力。
2. 轮次搜索共享：在一次规划执行中建立共享搜索缓存，按归一化查询复用结果，任务只读取共享证据。
3. 轻量规划：Planner/Re-Planner 使用快速模型配置；Re-Planner 只在任务失败、结果不足或存在未完成任务时调用。
4. 并行执行：将无依赖且同一轮可执行的任务并发运行，并保持结果按计划顺序合并。
5. 实时事件：新增搜索开始/完成、Task 开始、Task 结果增量、Task 完成事件；保留现有 `plan_update` 作为兼容快照。
6. 前端接入：将新事件映射到左侧链路和右侧任务卡片，兼容历史快照与旧 SSE。

## 关键契约

- 新事件均为 SSE `event` 名称 + JSON `data`，旧客户端仍可仅消费 `plan_update`、`done`、`plan_done`。
- Task 字段新增字段全部可选：`search_status`、`search_results`、`streaming_result`。
- 搜索失败不阻塞非搜索任务，Task 结果必须披露证据不可用状态。
- 并行任务异常隔离，单个任务失败不会丢失其他任务结果。

## 验收标准

- 搜索任务默认不触发全文 scrape；摘要结果仍能进入任务和最终报告。
- 同一轮相同查询只产生一次外部搜索请求。
- 没有失败/未完成任务时不额外调用 Re-Planner。
- 互不依赖任务可并行执行，结果顺序稳定。
- SSE 至少能看到 `search_started`、`search_completed`、`task_started`、`task_delta`、`task_completed`。
- 前端类型检查、后端语法和自主规划回归测试全部通过。
